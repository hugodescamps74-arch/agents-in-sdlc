Copilotをエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。作業は開発者のマシン上でリアルタイムに進むため、VS CodeのCopilot Chatでは、各ツール呼び出しやファイル編集の状況を確認できます。差分をインラインで確認し、変更ごとに適用または却下できます。また、エディターを離れずに追加のプロンプトを送って、作業を調整したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して適用します。
- セッションの途中でエージェントに指示し、ハイコントラストモードに加えてライトモードの切り替え機能を追加します。

## シナリオ

[演習4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を加えて作業を拡張します。

## Copilotの進捗を監視する

Copilot Chatビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と**Keep**/**Undo**の操作とともに、チャット内に表示されます。

1. 演習4で使用したCopilot Chatビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - **Keep**を選択すると変更を適用します。
    - **Undo**を選択すると変更を元に戻し、もう一度作業するようエージェントに依頼します。
4. チャットの上部にある**Files changed**の表示を開くと、このセッション中にエージェントが変更したファイル一式を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められると、エージェントは一時停止して**Allow**を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けることで、エージェントはこれまでの作業に関するコンテキスト（変更したコンポーネント、採用したスタイル、設定したローカルストレージのパターンなど）を保持できます。

1. Copilot Chatの入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    よい出来です。ハイコントラストの切り替え機能と並べて、ライトモードの切り替え機能も追加してください。同じ方法でライトモードを実装し、ローカルストレージに設定を保存して、同じユーザーインターフェース（UI）領域から利用できるようにしてください。ハイコントラストとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントはすでに行った変更を調べ、新しい作業を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに**Keep**または**Undo**を選択します。
4. エージェントが意図と異なる方法で作業を進めている場合は、たとえば切り替えUIを望まない形でリファクタリングしようとしている場合など、チャット入力欄の横にある**Stop**ボタンで停止し、補足のメッセージを送信します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すよりも早く調整できます。追加のプロンプトで変更を依頼します（「Cascading Style Sheets（CSS）を簡潔にして、セレクターの重複ではなくCSS変数を使ってください」）、方向を修正します（「3つ目のトグルは追加せず、ライトモードを既存の設定パネルに組み込んでください」）、作業範囲を広げます（「両方の切り替え機能にキーボードショートカットも追加してください」）。

## 作業ファイルをレビューする

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Codeで**Source Control**ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astroコンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications（ARIA）属性、キーボード操作、セマンティックなHyperText Markup Language（HTML）、ローカルストレージによる保存など、カスタムエージェントが指示したアクセシビリティのパターンが反映されていることを確認します。
4. 内容に問題がなければ、Source Controlパネルで変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chatのエージェントモードを使って、進行中のセッションを監視し、誘導しました。ファイル編集のたびに内容を確認し、適用または却下し、コンテキストを保持したまま追加のプロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を適用または却下する
- 追加のプロンプトで進行中のセッションを誘導する

[次のレッスン][next-lesson]では、アクセシビリティ作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが作成した変更を確認します。

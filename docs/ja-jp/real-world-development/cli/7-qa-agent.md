これまでに `quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーのフィルタリング動作を確認しました。次は、これらの機能を明確な品質保証 (QA) プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリングの Issue に照らし合わせて指摘事項を確認します。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザーでの動作を一貫した方法で確認したいと考えています。カスタムエージェントを使うと QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する、専門分野に特化した Copilot です。プロファイルでは、エージェントの目的、指示、利用できるツールを指定します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、これらの機能を要件の評価と結果の報告にどう使うかを Copilot に指示します。QA プロファイルは、他の機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを Copilot に作成してもらいます。このプロファイルでは、QA が実施するチェックと、その作業の境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を Issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、カバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示しながら pass、fail、blocked のいずれかで報告してください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしてはいけません。

   まずプロファイルだけを作成してください。内容を確認します。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の進め方と制約を正しく反映したことを確認します。これにより、確認だけを依頼したのにプロファイルが不完全だったり、エージェントが想定を超えて機能を変更したりするのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は任意ですが、含めるとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件から確認を始め、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を示して報告し、実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしないことを確認します。
5. いずれかの役割や制約が抜けている場合は、続行する前に既定のエージェントに修正を依頼します。

## Issue を基に QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。QA がすでにある Issue と計画時の決定を利用できるように、プロファイルを作成した後、同じフィルタリングの会話を再開して QA を選択します。

1. 次のプロンプトを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェントの一覧に表示されない場合があります。次のコマンドで有効にできます。

2. 次のプロンプトを使って、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   Issue と計画で決めた内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業を進める様子を確認します。
4. 完了したら、エージェントが出したレポートを読みます。

## まとめと次のステップ

再利用可能な専門的役割をワークフローに追加し、その成果を確認しました。このレッスンでは、次のことを行いました。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認しました。
- 再利用可能な品質保証プロファイルを作成して確認しました。
- QA エージェントを選択し、フィルタリングの Issue に照らし合わせて指摘事項を確認しました。

これで、実装、スキルの更新、QA プロファイル、テスト、検証レポートがそろい、レビューの準備ができました。次は、[機能の PR にまとめ、Agent Merge を使います][next-lesson]。

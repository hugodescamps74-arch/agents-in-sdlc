使用代理模式时，GitHub Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会在你的计算机上实时进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以在聊天中查看每个差异，单独接受或拒绝更改，也可以通过后续提示词引导对话、完善或扩展工作，全程无需离开编辑器。

本练习将帮助你：

- 实时监控无障碍代理的工作；
- 审查并接受建议的文件编辑；
- 在会话进行期间引导代理，在高对比度模式之外添加浅色模式开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义代理正在实现高对比度模式。工作进行期间，设计团队又提出一项需求：他们也希望为觉得默认主题太暗的用户添加浅色模式开关。你无需从头开始新对话，可以引导当前会话扩展工作范围。

## 监控 Copilot 的进度

Copilot Chat 视图会显示代理执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中内联显示差异，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 代理工作期间，滚动聊天内容，查看每次工具调用。你会看到文件读取、文件编辑以及代理请求运行的终端命令。
3. 代理提出文件编辑时，差异会内联显示：
    - 选择 **Keep**，接受更改。
    - 选择 **Undo**，撤销更改，让代理再次尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看代理在本次会话中修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如需要运行终端命令），代理会暂停并显示 **Allow** 提示。只批准你确认安全的命令。

5. 等待代理完成高对比度模式。完成后，你会看到总结更改内容的最终消息。

## 引导代理添加浅色模式

高对比度模式实现后，你将继续在同一对话中添加浅色模式开关。由于延续了当前会话，代理会保留此前工作的上下文，包括修改过的组件、使用的样式方案和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示词：

    ```plaintext
    做得很好！现在请在高对比度开关旁添加浅色模式开关。浅色模式应采用相同模式，通过本地存储持久保存，并且可从同一用户界面（UI）区域访问。用户应能分别启用高对比度和浅色模式。
    ```

2. 代理会接着此前的工作，探索已有更改并提出浅色模式相关修改。
3. 与高对比度模式一样，逐项审查新更改。对每项差异使用 **Keep** 或 **Undo**。
4. 如果代理的方向不符合预期（例如尝试重构你不想改动的开关 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送说明要求的后续消息。

> [!TIP]
> 引导进行中的会话比从头开始更快。可以用后续提示词要求调整（“简化层叠样式表（CSS），改用 CSS 变量，避免重复选择器”）、纠正方向（“不要添加第三个开关，将浅色模式集成到现有设置面板中”）或扩展范围（“还要为两个开关添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查代理修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。你应会看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改文件并查看差异。确认其中体现了自定义代理要求的无障碍模式，包括无障碍富互联网应用（ARIA）属性、键盘导航、语义化超文本标记语言（HTML）和本地存储持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。你将在[下一课][next-lesson]中发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 代理模式监控并引导了正在进行的会话：逐项审查文件编辑、接受或拒绝更改，并发送后续提示词扩展工作，同时保留现有上下文。

本练习中，你：

- 实时监控了代理的工作；
- 审查并接受了建议的文件编辑；
- 在会话进行期间通过后续提示词引导了代理。

在[下一课][next-lesson]中，你将发布无障碍功能的拉取请求，并审查本实验中本地自定义代理生成的更改。
